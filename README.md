# 云顶山景区观光车排队上车与站点调度平台

把**票务、排队、车辆、站点、退票**联动起来的全栈演示系统：游客、站点工作人员、司机、调度中心、客服/主管、财务、运营复盘围绕**同一张车票 / 同一班车**协同处理，目标是减少热门站点拥堵，并在异常（满载跳站、误乘反方向、老人优先争议、车辆故障、司机交班延误、暴雨停运、退票争议）发生时自动联动所有相关方。

- 后端：NestJS 10 + TypeORM（**默认 SQLite，零外部依赖；可通过环境变量切换 MySQL**）
- 前端：React 18 + Vite + Ant Design 5
- 启动后自动建表并写入演示种子数据（2 条线路 / 10 个站点 / 6 辆车 / 4 名司机 / 7 张票，含 1 起**误乘反方向换乘在途**场景）

## 一、本地启动

需要 Node.js ≥ 18（开发环境为 Node 22）。

### 方式 A：Docker Compose 一键启动（推荐）

需要本机已安装 Docker（含 `docker compose` 插件）：

```bash
docker compose up --build
```

- 前端（含 API 反代）：<http://localhost:8080>
- 后端 API：容器内 `server:3001`（由前端容器反代，无需暴露）
- SQLite 数据持久化在 Docker 命名卷 `server-data`，删除卷即可重置：
  ```bash
  docker compose down -v
  ```

### 方式 B：本地双终端开发启动

需打开**两个终端**：

```bash
# 终端 1：后端（端口 3001）
cd server
npm install            # 如遇 EACCES 可加 --cache /tmp/npm-cache
npm start
# 看到 [scenic-shuttle] API listening on http://localhost:3001/api 即成功
# 首次启动自动建表 + 写入种子数据

# 终端 2：前端（端口 5173，/api 自动代理到 3001）
cd web
npm install
npm run dev
```

浏览器打开 <http://localhost:5173> ，左侧切换 7 个工作台：**游客 / 站点工作人员 / 司机 / 调度中心 / 客服·主管 / 财务 / 运营复盘**。

> 如遇 npm 缓存权限错误（`EACCES ~/.npm`），可加参数：`npm install --cache /tmp/npm-cache`。

### 重置演示数据

停止后端后删除 SQLite 文件再启动即可：

```bash
rm -f server/data/app.sqlite
cd server && npm start
```

## 三、核心业务与异常联动

| 场景 | 平台行为 |
| --- | --- |
| 购票 | 记录入园时间、起终点站、同行人数、婴儿车/老人/儿童、轮椅需求、预计游览路线；无障碍/老人票自动进入**优先组** |
| 站点排队 | 平板看板：排队人数、已检票数、车辆位置、座位余量、轮椅位、天气、道路管制；扫码入队自动校验始发站 |
| 检票 | 一键叫号按「优先组优先 + 同组 FIFO」；自动校验**方向**与座位/轮椅位 |
| 热门站排队过长 | 排队超站台容量 1.2 倍自动生成 `long_queue` 事件并推送调度加车建议 |
| 满载跳站 | 车辆 GPS 到站（电子围栏）发现余座为 0：自动登记跳站、站台游客转回排队、通知调度加车并记录事件 |
| **误上反方向 · 换乘衔接** | 检票口方向不符自动拦截；游客坚持可「强制放行」，平台立即**按票种、车辆当前位置、剩余路线生成换乘方案**（下一站下车换乘 / 调度接驳 / 原车折返 / 退票引导），同步提醒**司机与下一站工作人员**；确认方案后**下一站再次同步提醒、行程变化推送游客端**；游客到站由工作人员**优先通道直接交接、不重新排队、不另收车费**；平台记录**游客是否接受**与**是否产生额外等待**；游客拒绝换乘或选择退票引导由平台/工作人员转退票，**客服处理时可看到完整行程变化**；游客确认后方案归档、事件闭环 |
| 老人优先争议 | 站务一键上报 `priority_dispute`，客服工作台接单并可闭环 |
| 车辆故障 | 司机上报 → 车辆转故障、在运班停运、调度派备车、游客无责退票，事件串联票/车/班 |
| 司机交班延误 | 上报后其计划班自动变「延误」并禁止再派班，看板与调度建议同步提示 |
| 暴雨临时停运 | 天气达橙色（level≥3）：一键停运所有在运/计划班；已上车票转客服无责退票，候乘游客引导离队退票；停运期间派班被阻断 |
| 退票 | 游客/站务发起 → 生成退票单+事件 → 客服核准/驳回；争议一键**升级客服主管**终局裁决 → 财务出账；每一步都写在车票时间线上 |
| 团队包车 | 申请→调度配车（校验座位/轮椅位）→车辆预留→开始用车→完单释放 |
| 无障碍 | 无障碍车辆标识、轮椅位库存、轮椅位检票占用、包车轮椅位校验 |
| 司机安全检查 | 发车前 6 项检查；任一不合格车辆自动转维保且派班被阻断 |
| 站点广播 / 限流 | 本站或全线广播；热门景点可设每小时限流人数 |
| 电子围栏 | 车辆进/出站自动记录，驱动满载跳站判定与车辆位置更新 |
| 派班校验 | 电量<20%、充电/维保/故障、包车预留、司机未签到/休息/交班延误/超时未休/达工时上限、安检未过、道路封闭、暴雨预警——任一不满足即阻断并一次性返回全部原因 |
| 运营复盘 | 站点等待（平均/最长/被跳组数）、车辆利用率（上座率/里程/电量）、投诉原因分布、退票成本按责任归类、**误乘换乘治理（接受/拒绝/额外等待/关联退票/平均额外等待）**、KPI 总览 |

## 四、推荐验证路径（手工点点看）

### 误乘反方向换乘（本功能主线）

1. **游客页**：输入种子误乘票 `T20261001-007`（林阿婆），可见顶部**红色「行程变化通知 · 误乘反方向换乘方案」**卡片：平台建议在百花园下车、工作人员接应、换乘上行车、不另收费。
2. **司机页**：切到**赵师傅(4)**，顶部出现「误乘反方向游客提醒」（游客在 V03 上、下一站百花园），点**我已知悉 · 到站交接**。
3. **站务页**：切到**百花园(2)**，顶部红色「误乘反方向 · 本站接应提醒」卡片可查看方案；此时方案尚未确认。
4. **调度中心页** →「误乘换乘」Tab：看到待确认方案（含各方提醒状态），点**确认方案**，选择「下一站下车换乘上行」并可指定衔接班（种子 `TR…-002`）→ 确认后下一站再次提醒、游客端同步。
5. 回**游客页**：方案变为「已确认待接应」，点**接受方案**（或点「不接受，想退票」走退票链路）。
6. 回**百花园站务页**：点**车辆到站 · 已接到游客（免排队交接）**，填写实际额外等待分钟数 → 游客直接以优先交接身份进入队列（页面队列显示「误乘换乘交接·免排队」标签），无需重新排队。
7. 让衔接班开始上客并给该交接队列检票 → 方案自动变为**换乘完成**；游客页点**确认行程变化并归档**，事件闭环。
8. **运营复盘页**：底部「误乘反方向换乘治理」卡片显示接受数、额外等待人次、平均额外等待等。

拒绝/退票链路：在第 5 步选择「不接受，想退票」→ 百花园站务页点「游客要求退票 · 代发起」（或由方案引导）→ **客服页**退票单出现「误乘换乘」标记，点**查看完整行程**可看到方案与全部事件时间线 → 客服核准 → **财务页**出账 → 方案归档。

> 也可以从检票口完整走一遍触发：东门站务给一张上行票，用「强制放行」检入下行班车（需先在调度显式以 `direction=backward` 派一班环线反向车），平台同样自动生成换乘方案并通知司机/下一站。

### 其他既有场景

1. **游客页**：买一张无障碍优先票（勾老人+轮椅）→ 复制票号；再查种子票看车票时间线。
2. **站务页（选东门枢纽）**：输入新票号「扫码排队」→ 用「一键叫号」给上行班次检票，观察**优先组先被叫到**；尝试给其他游客检反方向班观察方向拦截。
3. **司机页**：选王建国+V01，完成 6 项安检；切换李海燕看强制休息提示；用「到站/离站」驱动班车（先在调度把车卖满，再到站可看到**满载跳站**弹窗）。
4. **调度中心页**：直接派班 V06 或选李海燕，观察**多重阻断原因**；「天气与管制」里把预警改成等级 3（暴雨橙色）→ 出现**一键停运**；包车页代客登记 18 人+2 轮椅团队，先配小车被拒、再配 V05 成功。
5. **客服页**：处理退票（同意/驳回/升级主管），在「主管争议裁决」完成终局裁决。
6. **财务页**：对已核准退票单笔「出账退款」。
7. **运营复盘页**：查看站点等待、车辆利用率、投诉原因、退票成本图表、误乘换乘治理卡片与 KPI。
8. 回到**游客页**查询被退款车票，可见游客→调度→站务→司机→客服→财务的完整时间线。

## 五、切换 MySQL（可选）

默认 SQLite 零配置运行。如需使用 MySQL（8.x），先建库：

```sql
CREATE DATABASE scenic_shuttle DEFAULT CHARACTER SET utf8mb4;
```

然后用环境变量启动后端（`synchronize: true` 会自动建表）：

```bash
cd server
DB_TYPE=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASSWORD=root DB_NAME=scenic_shuttle \
  npm start
```

## 六、主要接口一览（前缀 `/api`）

- 票务：`POST /tickets`、`GET /tickets/:id`（含票的完整事件时间线与换乘方案）、`GET /tickets/code/:code`、`POST /tickets/:id/refund`
- 站点：`GET /overview`、`GET /routes`、`GET /stations/:id/board`（含本站换乘接应提醒 `transfers`）、`POST /stations/:id/enqueue`、`POST /stations/:id/board-next`、`POST /queue/:id/board`（方向不符拦截；`force:true` 强制放行并自动生成换乘方案）、`POST /queue/:id/dispute`、`POST /broadcasts`、`PATCH /stations/:id`
- 调度：`GET /dispatch/dashboard`、`POST /trips`、`POST /trips/:id/start-boarding|arrive|leave|complete`、`POST /safety-checks`、`POST /vehicles/:id/fault|charge|repair`、`POST /drivers/:id/duty|handover-delay`、`POST /weather`、`POST /road-controls`、`POST /dispatch/storm-suspend|resume`、`GET /geofence-events`、`POST /charters`、`POST /charters/:id/assign|status`
- **误乘换乘**：`GET /transfer-plans`（可按 `status/ticketId/tripId/stationId` 过滤）、`GET /transfer-plans/stats`、`GET /transfer-plans/ticket/:ticketId`、`POST /transfer-plans`（车上发现误乘时补建）、`POST /transfer-plans/:id/confirm`、`POST /transfer-plans/:id/driver-ack`、`POST /transfer-plans/:id/staff-meet|staff-note`、`POST /transfer-plans/:id/visitor-decide`、`POST /transfer-plans/:id/request-refund`、`POST /transfer-plans/:id/archive|cancel`
- 客服/财务：`GET /service/workbench`（退票单附 `transferPlans` 与 `incidentTimeline` 完整行程变化）、`POST /refunds/:id/approve|reject|escalate|supervisor-decide|pay`、`POST /incidents/:id/take|resolve`、`GET /incidents`
- 复盘：`GET /ops/report`（含 `transfers` 误乘换乘治理统计）
