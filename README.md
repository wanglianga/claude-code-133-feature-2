# 云顶山景区观光车排队上车与站点调度平台

把**票务、排队、车辆、站点、退票**联动起来的全栈演示系统：游客、站点工作人员、司机、调度中心、客服/主管、财务六类角色围绕**同一张车票 / 同一班车**协同处理，目标是减少热门站点拥堵，并在异常（满载跳站、误乘反方向、老人优先争议、车辆故障、司机交班延误、暴雨停运、退票争议）发生时自动联动所有相关方。

- 后端：NestJS 10 + TypeORM（**默认 SQLite，零外部依赖；可通过环境变量切换 MySQL**）
- 前端：React 18 + Vite + Ant Design 5
- 启动后自动建表并写入演示种子数据（2 条线路 / 10 个站点 / 6 辆车 / 4 名司机 / 7 张在途票与排队 / 1 个误乘换乘方案）
- **一键启动**：提供 Dockerfile 与 docker-compose.yml，单容器/单端口（3001）同时提供页面与 API

---

## 〇、一键启动（Docker，推荐快速体验）

需要 Docker（含 Compose 插件）。在仓库根目录执行：

```bash
docker compose up --build
```

启动后浏览器打开 <http://localhost:3001> 即可使用（前端静态文件由后端同源托管，API 前缀 `/api`）。
SQLite 数据保存在 compose 卷 `scenic-sqlite` 中；停止后重新启动数据保留。

重置演示数据：

```bash
docker compose down -v   # 删除数据卷
docker compose up --build
```

> 本机不想用 Docker 时，按下面的「一、本地启动」分别起前后端两个进程。

## 一、本地启动

需要 Node.js ≥ 18（开发环境为 Node 22）。需打开**两个终端**：

### 1. 启动后端（端口 3001）

```bash
cd server
npm install
npm start
# 看到 [scenic-shuttle] API listening on http://localhost:3001/api 即成功
# 首次启动自动建表 + 写入种子数据
```

### 2. 启动前端（端口 5173）

```bash
cd web
npm install
npm run dev
```

浏览器打开 <http://localhost:5173> ，左侧切换 7 个工作台：**游客 / 站点工作人员 / 司机 / 调度中心 / 客服·主管 / 财务 / 运营复盘**。

> 如遇 npm 缓存权限错误（`EACCES ~/.npm`），可加参数：`npm install --cache /tmp/npm-cache`。

### 重置演示数据

停止后端后删除 SQLite 文件再启动即可：

```bash
rm -f server/data/app.sqlite
cd server && npm start
```

## 三、核心业务与异常联动

| 场景 | 平台行为 |
| --- | --- |
| 购票 | 记录入园时间、起终点站、同行人数、婴儿车/老人/儿童、轮椅需求、预计游览路线；无障碍/老人票自动进入**优先组** |
| 站点排队 | 平板看板：排队人数、已检票数、车辆位置、座位余量、轮椅位、天气、道路管制；扫码入队自动校验始发站 |
| 检票 | 一键叫号按「优先组优先 + 同组 FIFO」；自动校验**方向**与座位/轮椅位 |
| 热门站排队过长 | 排队超站台容量 1.2 倍自动生成 `long_queue` 事件并推送调度加车建议 |
| 满载跳站 | 车辆 GPS 到站（电子围栏）发现余座为 0：自动登记跳站、站台游客转回排队、通知调度加车并记录事件 |
| 误上反方向 | 检票口方向不符自动拦截；游客坚持「强制放行」后，平台按**票种/当前位置/剩余路线**自动生成换乘方案：同步提醒**司机**（车上安抚、勿折返）与**下一站工作人员**（车门接应、免重新排队），自动匹配或由调度锁定对向接驳班；游客端收到方案并**接受/拒绝**，平台记录**是否产生额外等待**；车辆电子围栏到下车站自动联动，下一站确认换乘，**游客确认后归档**；客服处理退票时可看到完整行程变化 |
| 老人优先争议 | 站务一键上报 `priority_dispute`，客服工作台接单并可闭环 |
| 车辆故障 | 司机上报 → 车辆转故障、在运班停运、调度派备车、游客无责退票，事件串联票/车/班 |
| 司机交班延误 | 上报后其计划班自动变「延误」并禁止再派班，看板与调度建议同步提示 |
| 暴雨临时停运 | 天气达橙色（level≥3）：一键停运所有在运/计划班；已上车票转客服无责退票，候乘游客引导离队退票；停运期间派班被阻断 |
| 退票 | 游客/站务发起 → 生成退票单+事件 → 客服核准/驳回；争议一键**升级客服主管**终局裁决 → 财务出账；每一步都写在车票时间线上 |
| 团队包车 | 申请→调度配车（校验座位/轮椅位）→车辆预留→开始用车→完单释放 |
| 无障碍 | 无障碍车辆标识、轮椅位库存、轮椅位检票占用、包车轮椅位校验 |
| 司机安全检查 | 发车前 6 项检查；任一不合格车辆自动转维保且派班被阻断 |
| 站点广播 / 限流 | 本站或全线广播；热门景点可设每小时限流人数 |
| 电子围栏 | 车辆进/出站自动记录，驱动满载跳站判定与车辆位置更新 |
| 派班校验 | 电量<20%、充电/维保/故障、包车预留、司机未签到/休息/交班延误/超时未休/达工时上限、安检未过、道路封闭、暴雨预警——任一不满足即阻断并一次性返回全部原因 |
| 运营复盘 | 站点等待（平均/最长/被跳组数）、车辆利用率（上座率/里程/电量）、投诉原因分布、退票成本按责任归类、KPI 总览 |

## 四、推荐验证路径（手工点点看）

1. **游客页**：买一张无障碍优先票（勾老人+轮椅）→ 复制票号；再查 `T20260925-001` 看车票时间线。
2. **站务页（选东门枢纽）**：输入新票号「扫码排队」→ 用「一键叫号」给班次 `TR…-001` 检票，观察**优先组先被叫到**；尝试给其他游客检本班观察方向拦截。
3. **司机页**：选王建国+V01，完成 6 项安检；切换李海燕看强制休息提示；选陈志强+V02 用「到站/离站」驱动班车（先在调度把车卖满，再到站玻璃栈道可看到**满载跳站**弹窗）。
4. **调度中心页**：
   - 直接派班 V06 或选李海燕，观察**多重阻断原因**；
   - 用 V01+王建国派班成功；
   - 「天气与管制」里把预警改成等级 3（暴雨橙色）→ 出现**一键停运**；
   - 包车页代客登记 18 人+2 轮椅团队，先配小车被拒、再配 V05 成功。
5. **客服页**：处理退票（同意/驳回/升级主管），在「主管争议裁决」完成终局裁决；「误乘换乘跟进」Tab 可查看所有换乘方案、代误乘游客发起退票。
6. **误上反方向换乘（新）**：
   - 站务页选**玻璃栈道**，给一位票面下行的游客检上行班时先被拦截；点「强制放行」→ 自动生成换乘方案（司机、下一站同步收到提醒）。
   - 司机页切换到该班车：可见车上误乘游客与方案，点「确认收到提醒」；用「到站」上报下车站，弹出接应提示。
   - 站务页切到**下车站**：顶部出现「下一站换乘接应提醒」，确认接应 → 待游客接受后「确认游客已换乘」并登记实际额外等待。
   - 游客页查询该票：查看方案五步引导 →「接受方案」；换乘完成后「确认并归档」。
   - 调度页：换乘协同卡片可「锁定/改派接驳班次」。
   - 客服页：对该票代发起/审核退票时，点「误乘行程变化」可看到完整方案、是否接受、实际额外等待。
   - 种子数据自带一条进行中的方案：游客页查 `T…-007`（郑洁），或站务页选东门枢纽即可看到接应提醒。
7. **财务页**：对已核准退票单笔「出账退款」。
8. **运营复盘页**：查看站点等待、车辆利用率、投诉原因、退票成本四张图表与 KPI。
9. 回到**游客页**查询被退款车票，可见游客→司机→下一站→调度→客服→财务的完整时间线。

### 自动化验证（后端端到端，81 项断言）

后端启动状态下另开终端（建议先使用全新种子数据库）：

```bash
rm -f server/data/app.sqlite   # 可选：重置演示数据后重启后端
node server/scripts/scenario-check.mjs
# 输出 81 通过 / 0 失败
```

该脚本覆盖：优先检票、始发站校验、派班多重阻断、安检不合格转维保、反方向拦截、**误上反方向换乘方案全流程（生成/司机与下一站提醒/游客接受与拒绝/到站联动/实际额外等待/客服退票可见行程变化/游客确认归档）**、满载跳站、车辆故障、退票核准→财务出账、争议升级主管裁决、暴雨停运与派班阻断、交班延误推迟下一班、包车座位/轮椅校验、广播限流、车票时间线、复盘报表。

## 五、切换 MySQL（可选）

默认 SQLite 零配置运行。如需使用 MySQL（8.x），先建库：

```sql
CREATE DATABASE scenic_shuttle DEFAULT CHARACTER SET utf8mb4;
```

然后用环境变量启动后端（`synchronize: true` 会自动建表）：

```bash
cd server
DB_TYPE=mysql DB_HOST=127.0.0.1 DB_PORT=3306 DB_USER=root DB_PASSWORD=root DB_NAME=scenic_shuttle \
  npm start
```

## 六、主要接口一览（前缀 `/api`）

- 票务：`POST /tickets`、`GET /tickets/:id`（含票的完整事件时间线）、`GET /tickets/code/:code`、`POST /tickets/:id/refund`
- 站点：`GET /overview`、`GET /routes`、`GET /stations/:id/board`、`POST /stations/:id/enqueue`、`POST /stations/:id/board-next`、`POST /queue/:id/board`、`POST /queue/:id/dispute`、`POST /broadcasts`、`PATCH /stations/:id`
- 调度：`GET /dispatch/dashboard`、`POST /trips`、`POST /trips/:id/start-boarding|arrive|leave|complete`、`POST /safety-checks`、`POST /vehicles/:id/fault|charge|repair`、`POST /drivers/:id/duty|handover-delay`、`POST /weather`、`POST /road-controls`、`POST /dispatch/storm-suspend|resume`、`GET /geofence-events`、`POST /charters`、`POST /charters/:id/assign|status`
- 客服/财务：`GET /service/workbench`、`POST /refunds/:id/approve|reject|escalate|supervisor-decide|pay`、`POST /incidents/:id/take|resolve`、`GET /incidents`
- 误乘换乘：`POST /transfers/plans`（按票种/当前位置/剩余路线生成方案）、`GET /transfers/plans`（支持 `status/ticketId/driverId/stationId` 过滤）、`GET /transfers/by-ticket/:ticketId`、`POST /transfers/plans/:id/accept|decline|driver-ack|station-ack|assign-pickup|complete|archive`
- 复盘：`GET /ops/report`
